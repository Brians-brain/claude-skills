# 階段邊界

**階段**是一個 session 中的一段工作：拷問、實作、QA。這個定義刻意模糊：當你心裡想「好，那部分做完了」，一個階段就結束了。

**階段邊界**是兩個階段之間的空隙，也是這個決策唯一該發生的地方。階段中途沒有決策要做：繼續，或把剩下的工作拆給子 agent。在階段中途 compact，會讓 agent 失去脈絡。

## 五個選項

| 選項 | 它做什麼 |
| ------------ | --------------------------------------------------------------- |
| **繼續** | 待在這個 session。完全沒有情境切換。 |
| **`/clear`** | 清空情境視窗，從零開始。 |
| **`/handoff`** | 寫一個可攜的 markdown 檔，並在任何地方用它啟動一個 session。 |
| **子 agent** | 把任務送到它自己的情境視窗，並拿回一份報告。 |
| **`/compact`** | 壓縮這個情境，並用摘要啟動一個新 session。 |

## 決策樹

在邊界上由上往下走。第一個**是**就決定了。

**1. 你能在這個 session 繼續嗎？** 兩件事會讓答案是「是」：下一個階段需要這個階段作為**一手資料**，或者你還有足夠的[聰明區](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（約 15 萬 token）容納下一個階段。拷問 → 實作是標準的「是」：實作要的是原汁原味的推理，而不是推理的摘要。繼續不花任何成本，也不失去任何東西，所以在考慮其他任何選項之前，先排除它。

**2. 這個情境和接下來的事無關嗎？** 這個 session 中的一切（探索、決策、死路）都可以丟掉嗎？如果是，就 **`/clear`**。這是整個棋盤上最便宜的一步：不花時間，還把整個視窗還給你。`/clear` 也不是終點：舊的 session 仍然可以恢復。

弄錯的代價是單向的。清掉一個**相關**的情境，你就失去了你所建造的東西背後的**為什麼**，而且再怎麼重讀 diff 也拿不回來。

**3. 你需要交棒嗎？** `/handoff` 的用途很窄。只有在以下情況才需要它：

- 換到一個**新的 harness**（Claude → Codex），
- 移到一個**新的目錄**或 repo，
- 把工作交給一位**同事**，
- 或在**階段中途**發現一個支線任務、想把它分出去而不打斷手上的事。

這份清單就是全部的條件。`/handoff` 換來的是**可攜性**：一個能帶著走的檔案。如果沒有東西要帶走，你就不需要它。

**4. 這個任務能在無人看管下完成嗎？** 它的範圍夠明確，能在你離開鍵盤、不需要引導的情況下執行嗎？那就把它送給一個**子 agent**，讓這個 session 保持原樣。自動化審查是標準案例：agent 讀 diff 並回報，它做的時候不需要你。

**5. 否則，`/compact`。** 相關的情境、同一個 harness、同一個目錄，而且你需要留在迴路中：這就是決策樹的落點，而且很常落在這裡。給它一個指示（`/compact 接下來要對這個區域做 QA`），讓摘要保留下一個階段需要的東西。

`/compact` 是**預設，而不是第一個伸手拿的**。它放在最底端，因為它上面的四個問題都更便宜或更精確。從這裡開始的人常見的失敗模式是：一個新的 session 對某個被摘要壓扁的決策充滿自信地出錯。

## 一手與二手資料

除了**繼續**之外，每一個選項都會把**一手資料**變成**二手資料**：實際發生的 session 被它的摘要取代。這個交換永遠是同樣的形狀：

| 來源 | 資訊 | 雜訊 | 活動空間 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手（繼續） | 完整 | 很多 | 很少 |
| 二手（`/compact`、`/handoff`） | 有損失 | 較少 | 很多 |

這就是為什麼問題 1 排第一。只有當留下來的成本大於它省下的，你才付出這個損失。

## 這些都是判斷題

這些問題不是客觀的：每一題都帶有個人品味，同一個邊界在不同的日子可能走向兩邊。價值在於**依序**問它們，而且在邊界上問，而不是在工作進行到一半時問。
