# 設計兩次（Design It Twice）

當使用者想為選定的加深候選探索不同的介面時，使用這個平行子 agent 模式。源自 Ousterhout 的「Design It Twice」：你的第一個想法不太可能是最好的。

使用 [SKILL.md](SKILL.md) 中的詞彙：**模組**、**介面**、**seam**、**轉接器**、**槓桿**。

## 流程

### 1. 說明問題空間

在派出子 agent 之前，先為選定的候選寫一段給使用者看的問題空間說明（繁體中文）：

- 任何新介面都必須滿足的限制
- 它會依賴哪些東西，以及這些依賴屬於哪一類（見 [DEEPENING.md](DEEPENING.md)）
- 一段粗略的示意程式碼，用來把限制具體化：不是提案，只是讓限制更具體的方式

把它給使用者看，然後立刻進入步驟 2。使用者閱讀與思考的同時，子 agent 平行工作。

### 2. 派出子 agent

平行派出 3 個以上的子 agent。每個都必須為加深後的模組產出**截然不同**的介面。

給每個子 agent 一份獨立的技術簡報（檔案路徑、耦合細節、[DEEPENING.md](DEEPENING.md) 中的依賴分類、seam 背後放什麼）。這份簡報和步驟 1 給使用者看的問題空間說明是分開的。給每個 agent 不同的設計限制：

- Agent 1：「最小化介面：最多 1–3 個進入點。最大化每個進入點的槓桿。」
- Agent 2：「最大化彈性：支援多種使用情境與擴充。」
- Agent 3：「為最常見的呼叫端最佳化：讓預設情境變得極其簡單。」
- Agent 4（若適用）：「針對跨 seam 的依賴，以 ports & adapters 為核心設計。」

在簡報中同時附上 [SKILL.md](SKILL.md) 的詞彙與 GLOSSARY.md 的詞彙，讓每個子 agent 的命名同時符合架構語言與專案的領域語言。

每個子 agent 產出：

1. 介面（型別、方法、參數，加上不變條件、呼叫順序、錯誤模式）
2. 呼叫端如何使用它的範例
3. 實作在 seam 背後藏了什麼
4. 依賴策略與轉接器（見 [DEEPENING.md](DEEPENING.md)）
5. 取捨：哪裡槓桿高、哪裡槓桿薄

### 3. 呈現與比較

逐一呈現每個設計，讓使用者能逐一消化，然後用文字比較它們。從**深度**（介面上的槓桿）、**局部性**（修改集中在哪裡）與 **seam 位置**來對照。

比較之後，給出你自己的建議：你認為哪個設計最強、為什麼。如果不同設計的元素能很好地結合，就提出一個混合方案。要有主見：使用者要的是明確的判斷，不是一份菜單。
