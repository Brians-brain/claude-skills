與使用者溝通使用繁體中文。

使用者要求進行**回顧**。你要提出的是改善 coding agent **工作環境**的建議，讓之後的執行更好。

## 步驟

1. 用 Skill tool 呼叫 `writing-for-agents`，取得寫作風格指南。

2. 閱讀使用者指定的 session 的一手資料。這可能代表要搜尋這台機器上的 session 紀錄。如果使用者沒有指定 session，預設為目前這一個。

3. 在以下類別中尋找可以改善的地方。

- **導航**：agent 找到正確檔案有多容易？檔案之間有沒有隱藏的相依？加一個**導航指標**會不會更容易？_使用時機_：這個 session 花了很久才找到某個資訊。
- **自動檢查**：有沒有自動檢查能抓到 agent 犯的錯？linting、型別檢查、測試、檔案系統 linter？先讀 repo 自己的檢查指令（`pyproject.toml`／`package.json` 中的 lint／check 設定、CI workflow），這樣「已經存在、但沒接上或默默壞掉的檢查」才會成為發現，而不是重新發明一個。一個沒有任何**護欄**的 repo（沒有 pre-commit hook，也沒有執行 lint／型別檢查／測試的 CI job）本身就是一個發現：沒有 lint 的 repo 是一個持續錯失的機會，而不是中性的預設。_使用時機_：agent 犯了一個自動檢查本可抓到的錯，或 repo 完全沒有護欄。
- **寫作規範**：**審查 agent** 是否應該得到一條新規則來執行？是否有既有規則應該移除或釐清？先把違規分類：**機械性**的違規（固定的語法模式、被禁止的 API、import 形式、檔案位置規則）就該用確定性的檢查處理，沒有例外：在 repo 自己的 linter 中加一條自訂規則、一個新的 pre-commit hook，或一個新的 CI job，看 repo 的語言與既有護欄哪個最便宜。預設是建立檢查，而不是寫規則。`CODING_STANDARDS.md` 只留給真正的**判斷題**（跨檔案的一致性、「符合周圍的風格」、任何護欄都無法取代的東西）。_使用時機_：審查 agent 沒抓到某個錯誤。
- **全域 AGENTS.md／CLAUDE.md**：有沒有引導指示應該移到寫作規範（或自動檢查）？_使用時機_：repo 中或使用者全域範圍的 AGENTS.md／CLAUDE.md 特別大。
- **工具經濟性**：agent 是否做了可以精簡的昂貴工具呼叫？有沒有特別浪費 token 的自訂工具（CLI、MCP）？_使用時機_：agent 做了昂貴的工具呼叫。
- **無效指令**：找出引導檔中不會改變 agent 行為的指示。_使用時機_：引導檔很大、難以管理。
- **資訊存取**：尋找增加 agent 資訊存取的機會。把開發伺服器的 log 導出、提供第三方服務的唯讀存取。_使用時機_：agent 拿不到某個關鍵資訊。

4. 依嚴重程度排序，把這些候選呈現給使用者。

## 參考

### 實作與審查

記住所有工作都會經過兩個階段：實作與審查。實作 agent 承受最大的**情境壓力**。它要負責探索、寫程式和除錯。

審查 agent 承受的情境壓力最小：它拿到的是一份 diff，不需要探索。它通常不需要寫程式或除錯。

這代表應該由審查 agent 負責執行寫作規範，而不是實作 agent。

### 檔案

你可以使用 repo 中的幾種檔案：

- `CLAUDE.md`／`AGENTS.md`：這些檔案會被推進任何在這個 repo 工作的 agent 的情境視窗。要非常節制地使用，通常只放指向其他檔案的**導航指標**。
- `CODING_STANDARDS.md`：這個檔案在審查時讀取，而不是實作時。如果規範檔超過 1,000 行，加上指向 docs 資料夾的**導航指標**。
- Docs：把 docs 當作參考檔，由其他檔案指向。寫新的之前，先找現有的。
- Skills：用 skill 來放文件（因為它的 description 會進入 agent 的情境視窗），或作為使用者呼叫的指令。遵循 `writing-for-agents` skill 的建議。
