# MISSION.md 格式

`MISSION.md` 放在工作區根目錄，記錄使用者學習這個主題的**理由**。每一個教學決策（接下來教什麼、推薦哪些資源、設計哪些練習）都應該能追溯到這份文件。

## 範本

```md
# 任務：{主題}

## 為什麼
{1–3 句話。使用者追求的具體、真實世界的目標。當他擁有這項技能時，他的生活或工作會有什麼改變？避免「為了理解 X」這種抽象說法，要追問背後真正的成果。}

## 成功的樣子
- {一件使用者將能做到、具體且可觀察的事}
- {另一件具體的事}
- {…}

## 限制
- {時間、預算、既有承諾、學習偏好，任何會限制做法的條件}

## 不在範圍內
- {使用者明確表示現在不想追的相鄰主題，用來保護近側發展區}
```

## 規則

- **一個工作區一個任務。** 如果使用者想學兩件不相關的事，就是兩個工作區。
- **具體勝過抽象。**「三個月內能獨立用頻譜分析儀完成客戶的雜散量測」勝過「學好 RF」。「把成本計算工具交給採購同事使用」勝過「學 Python」。
- **對模糊說法提出質疑。** 如果使用者說不出為什麼，在寫任何東西之前先訪談他。一個糟糕的任務比沒有任務還糟。
- **現實改變時就修正。** 任務會變。當使用者的目標移動時，更新這個檔案，不要讓過時的任務繼續引導之後的 session。
- **保持簡短。** 如果 `MISSION.md` 超過一個螢幕，它就不再是指南針，而變成一份計畫了。
