# 不在範圍內的知識庫

repo 中的 `.out-of-scope/` 目錄保存被拒絕的功能請求的持久紀錄。它有兩個用途：

1. **組織記憶**：記住一個功能為什麼被拒絕，讓 issue 關閉後理由不會遺失
2. **去重複**：當新進的 issue 與先前的拒絕相符時，skill 可以提出先前的決策，而不是重新爭論一次

## 目錄結構

```
.out-of-scope/
├── web-ui.md
├── erp-integration.md
└── realtime-pricing.md
```

一個**概念**一個檔案，而不是一個 issue 一個檔案。請求同一件事的多個 issue 歸在同一個檔案底下。

## 檔案格式

檔案應該以輕鬆、易讀的風格撰寫（繁體中文），比較像一份簡短的設計文件，而不是資料庫條目。用段落、程式碼範例和實例，把理由講清楚，讓第一次看到的人也覺得有用。

```markdown
# 網頁介面

本專案不提供網頁介面；它是一個以命令列與 Excel 輸出為主的工具。

## 為什麼不在範圍內

目前的使用流程是：採購同事提供 BOM Excel，工具輸出含成本與替代料的 Excel。
支援網頁介面需要：

- 一個長時間執行的伺服器，以及部署與維護它的人
- 使用者登入與權限管理
- 把目前的批次處理改寫成可以逐步回報進度的流程

這是重大的架構改變，不符合本專案「小而可靠的內部工具」的定位。
需要網頁介面的使用情境，應該由下游另外包裝。

```python
# 目前的進入點是為批次處理設計的，不是為請求／回應設計的：
def run(bom_path: Path, output_path: Path) -> None: ...
```

## 先前的請求

- #42：「可以做成網頁版嗎」
- #87：「希望業務能直接在瀏覽器上查成本」
```

### 為檔案命名

用簡短、描述性的 kebab-case 名稱表示概念：`web-ui.md`、`erp-integration.md`、`realtime-pricing.md`。名稱要夠好辨認，讓瀏覽目錄的人不用打開檔案就知道被拒絕的是什麼。

### 撰寫理由

理由要有實質內容：不是「我們不想要」，而是為什麼。好的理由會提到：

- 專案的範圍或理念（「本專案專注於 X；介面是下游的事」）
- 技術限制（「支援這個需要 Y，這和我們的 Z 架構衝突」）
- 策略決策（「我們選擇用 A 而不是 B，因為……」）

理由要耐久。避免提到暫時的狀況（「我們現在太忙」）；那不是真正的拒絕，而是延後。

## 什麼時候要檢查 `.out-of-scope/`

Triage 期間（步驟 1：收集情境），讀取 `.out-of-scope/` 中的所有檔案。評估新 issue 時：

- 檢查這個請求是否和既有的不在範圍內概念相符
- 依概念相似度比對，而不是關鍵字：「瀏覽器版」符合 `web-ui.md`
- 如果相符，提給維護者：「這和 `.out-of-scope/web-ui.md` 很像。我們之前拒絕過，因為［理由］。你現在的看法還一樣嗎？」

維護者可能會：

- **確認**：新 issue 被加到既有檔案的「先前的請求」清單，然後關閉
- **重新考慮**：刪除或更新那個不在範圍內的檔案，issue 照正常 triage 流程進行
- **不同意**：兩個 issue 相關但不同，照正常 triage 流程進行

## 什麼時候要寫入 `.out-of-scope/`

只有當一個 **enhancement**（不是 bug）以 `wontfix` 被**拒絕**時。這對 enhancement 類的 PR 和 issue 完全一樣適用：被拒絕的 PR 也記在這裡，讓同樣的請求不會以新程式碼的形式再回來。

當某個東西因為**已經實作**而以 `wontfix` 關閉時，**不要**寫在這裡。那是已經做好的功能，不是被拒絕的；記錄它會讓去重複檢查被錯誤的拒絕汙染。關閉留言改為指出該功能已經在哪裡。

流程：

1. 維護者決定某個功能請求不在範圍內
2. 檢查是否已經有相符的 `.out-of-scope/` 檔案
3. 如果有：把新 issue 附加到「先前的請求」清單
4. 如果沒有：建立一個新檔案，包含概念名稱、決策、理由，以及第一筆先前的請求
5. 在 issue 上留言說明決策，並提到那個 `.out-of-scope/` 檔案
6. 以 `wontfix` 標籤關閉 issue

## 更新或移除不在範圍內的檔案

如果維護者改變了對某個先前被拒絕概念的想法：

- 刪除那個 `.out-of-scope/` 檔案
- skill 不需要重新開啟舊 issue；它們是歷史紀錄
- 觸發重新考慮的那個新 issue，照正常 triage 流程進行
