與使用者溝通使用繁體中文。撰寫的文件本身用什麼語言，依照該文件既有的語言或使用者指定。

這是撰寫任何給 agent 讀的文件時的參考：skill、`AGENTS.md`／`CLAUDE.md`、透過指標連到的文件。包裝方式不同，寫法沒有不同：同樣的槓桿能讓每一種文件都變得可預測，因為 agent 每次執行時走的是同一套**流程**，而不是產出同一份輸出。

如果你寫的文件是 skill，請讀 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、呼叫方式的選擇，以及路由型 skill。

## 情境指標（Context pointers）

**情境指標**是存在 agent 情境中的一個參照：它點名某份不在情境中的材料，並寫明何時該去取用它。skill 的 description 就是一個情境指標；`AGENTS.md` 裡點名某份文件的一行，也是同一種東西。決定 agent 何時取用、以及取用得多可靠的，是指標的**措辭**，而不是它指向的目標。一份非讀不可的材料，如果指標措辭薄弱，就是一個「變異性 bug」：先把措辭磨利，只有磨利失敗時才把材料直接寫進來。

指標要做兩件事：說明這份材料是什麼，以及列出應該觸發取用它的**分支**（分支是文件處理的一種不同情況，不同次執行會走不同的路徑）。一個常駐載入的指標，每個字在每一輪都要付出代價，所以它比文件本體更需要嚴格修剪：

- **把主導詞放在最前面**：指標就是在那裡發揮觸發作用。
- **一個分支一個觸發詞。** 替同一個分支換名字的同義詞，等於把同一個分支寫兩次；合併它們，只保留真正不同的分支。
- **刪掉本體已經交代的身分說明。**

## 兩種負擔

你新增的每一份文件、每一個指標，都會花掉兩種預算之一：

- **情境負擔（context load）**：常駐材料對 agent 視窗的成本：`AGENTS.md` 裡的一行、一個 skill 的 description、任何每一輪都在情境裡的東西，不管有沒有觸發，都在消耗 token 和注意力。
- **認知負擔（cognitive load）**：對人的成本：有哪些文件存在、什麼時候該用哪一份。人就是索引。這不是要最小化的成本，而是人類主導權的代價：在需要人類判斷的地方花它，在不需要的地方移除它。

只透過指標取用的材料，用指標那一行的代價換掉了情境負擔；完全沒有指標的材料，則全部由認知負擔承擔。

## 資訊層級

一份文件由兩種內容組成：**步驟**（agent 依序執行的動作）和**參考**（依需要查閱的定義、規則、事實）。兩者可以自由混合：全是步驟（食譜）、全是參考（審查規則、本 skill），或兩者都有。核心決策是每一塊內容在**資訊層級**中的位置。這是一道依「agent 多快需要這份材料」排序的階梯：

1. **檔內步驟**是第一層：agent 依序要做的事。
2. **檔內參考**依需要查閱。常常是一組合理地平鋪的同層內容（例如一次審查的所有規則放在同一層），這是好的安排，不是壞味道。
3. **揭露式參考**被推到另一個檔案，透過情境指標取用，只有指標觸發時才載入。範圍從同資料夾的兄弟檔案，一直到完全外部、放在任何地方、任何文件都能指向的參考。

推下去的太少，頂層就臃腫；推下去的太多，就會把 agent 真正需要的材料藏起來。這個拉扯就是整個決策。

**漸進式揭露（progressive disclosure）**就是沿著階梯往下移（移出主檔案、放到指標後面），讓頂層保持清楚易讀。它主要不是為了省 token，而是保護層級的方法。分支是最乾淨的揭露判準：每個分支都需要的內容寫在檔內，只有部分分支會用到的內容推到指標後面。當文件有步驟時，本該揭露卻留在檔內的參考會把步驟埋起來，讓 agent 是否注意到它們變成擲硬幣：這是一個變異性槓桿，不只是可讀性問題。

**同處原則（co-location）**是檔案內的搭配原則：階梯決定一塊內容放**多深**，同處原則決定放好之後**旁邊放什麼**。把一個概念的定義、規則與注意事項放在同一個標題底下，不要分散，讓讀到其中一部分時，相關內容也一起被讀到。判準：文件讀起來應該像是為 agent 寫的說明文件。分組的材料讀起來是這樣，分散的材料不是。（這和重複不同：重複是同一個意思出現在兩個地方；分散是同一個意思被拆碎到很多地方。）

**蔓延（sprawl）**是這裡的失敗模式：文件就是太長，即使每一行都還有效、也不重複。注意力會在多出來的部分被稀釋，每多一行就多一行要保持相關。解藥就是這道階梯：把參考揭露到指標後面，並依分支或順序拆分，讓每條路徑只帶它需要的東西。

## 步驟與完成條件

每個步驟都要以一個**完成條件**結尾，也就是告訴 agent 這項工作已經完成的條件。它有兩個性質可以當作槓桿：

- **清晰度**：agent 能分辨完成與未完成嗎？模糊的界線（「達成理解」）會招致**過早完成**：在步驟真正完成前就結束，注意力滑向「把事情做完」。前方可見的步驟（**完成後步驟**）提供拉力；完成條件的清晰度提供阻力。依序防守：**先磨利界線**（局部且便宜）；只有當它本質上就模糊、**而且**你確實觀察到趕工現象時，才透過拆分順序把後面的步驟藏起來。藏起來只有在跨越真正的情境邊界時才有效（交接或派出子 agent；直接呼叫會讓後面的步驟留在情境裡，什麼也沒清掉）。
- **要求程度**：它要求多少。「每個被修改的模型都有交代」會逼出徹底的工作，「產出一份變更清單」則不會。要求程度驅動**跑腿工作（legwork）**，也就是 agent 在工作中做的挖掘，它潛藏在措辭裡，而不是寫成獨立步驟。它也不限於步驟：「每條規則都套用過」能約束一整塊平鋪的參考，就像「每個步驟都完成」約束一個序列一樣，這就是全參考型文件仍能帶有「窮盡」標準的方式。

最強的完成條件既可檢查、又要求窮盡。

## 什麼時候該拆分

把一份文件拆成兩份會花掉兩種負擔之一，所以只有當拆分值得時才拆：

- **依順序拆**：當完成後步驟誘使 agent 趕著做眼前的步驟時，把一串步驟拆開。讓它們不在視線內，能逼出更多針對眼前任務的跑腿工作。小心反方向：合併序列會讓每個步驟的後續步驟暴露在眼前，招致過早完成。
- **依呼叫方式拆**，skill 專屬：見 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 主導詞（Leading words）

**主導詞**是一個已經存在於模型預訓練中的精簡概念，agent 在執行文件時會用它來思考（例如 _lesson_、_fog of war_、_tracer bullets_）。它以單一詞彙的形式重複出現，而不是以句子重複，因此會累積出分散式的定義，並用最少的 token 錨定一整塊行為，因為它召喚的是模型早已具備的先驗知識。自創詞彙也行，前提是定義清楚；但一個自造的詞召喚不到任何先驗，你得用定義的 token 去付預訓練詞免費給你的東西。先找現成的詞。

它會錨定兩次。在本體中，錨定的是**執行**：每次這個詞出現，agent 都會採取同樣的行為；在平鋪的參考中，它會讓注意力聚焦在某一類要尋找的東西上。在指標中，錨定的是**呼叫**：當同一個詞同時出現在你的提示詞、文件和程式碼中時，agent 會把這套共同語言連到該材料，更可靠地取用它。

主動尋找可以用主導詞重構的地方：在三個地方各寫一次的三元組、一個花一整句話只為了比劃出一個想法的指標。每一處都在等著被收斂成一個詞：

- 「快速、確定、低開銷」→ _tight_（一個 _tight_ 的迴路）。
- 「一個你信得過的迴路」→ _red_，把模糊的關卡變成二元、可觀察的狀態（迴路在這個 bug 上會變 _red_，或不會）。

你會贏兩次：更少的 token，以及一個更銳利的鉤子讓 agent 掛上它的思考。假設每一份文件都帶著可以被主導詞取代的重述，主動去找出來。

**否定句**是這個槓桿旁邊的失敗模式：用禁止來引導，會把被禁止的行為拖進情境，讓它**更**容易出現，而不是更不容易。叫人「不要想大象」，腦中就只剩大象；否定只是一個弱修飾語，會被強烈激活的概念蓋過，所以禁令有一半會被讀成「去做這件事」。改寫成**正向**的提示：說明目標行為（「每則註解只寫一行」），讓被禁止的行為根本不被說出口。只有在它是無法用正向方式表達的硬性護欄時，禁令才值得保留；即使如此，也要搭配正向目標，讓注意力落在該做的事上。

## 修剪

- 每個意思只保留**單一真實來源**：一個權威的位置，讓修改行為時只需要改一個地方。**重複**（同一個意思出現在不只一個地方）會增加維護成本與 token，並讓這個意思在階梯上的顯著程度超過它應有的位置。（它是主導詞的意外反面：主導詞是刻意重複一個詞，而不是重複意思。）
- **環境**也是真實來源（`pyproject.toml`、`package.json` 的 scripts、設定檔、目錄結構、`--help` 輸出），重述環境的文件就是一份**快取**：一份查詢結果的副本，只有在查詢很昂貴時才值得它的負擔。快取 agent 自己查不到的東西：沒寫下來的慣例、某個選擇背後的理由、沒有任何設定檔會招認的陷阱。只需打開一個檔案、跑一個指令就查得到的東西，留給環境，它們在那裡不會過時。
- 檢查每一行的**相關性**：它還和這份文件要做的事有關嗎？一行會失去相關性，可能是因為它從來都和任務無關（純粹的說明，或一個應該揭露出去的分支），也可能是因為它描述的行為或世界改變了而變得過時。越短的文件越容易保持相關。沒有修剪紀律，預設的命運就是**沉積**：因為新增感覺安全、刪除感覺危險，過時的層一層層沉澱，直到你必須鑽探穿過它們才找得到仍然有效的內容。
- 逐句找出**無效指令（no-ops）**：模型本來就預設會遵守的指令，付出負擔卻什麼也沒說。判準（相較於預設，它有改變行為嗎？）是相對於模型的，而不是相對於讀者的：兩個人對某句是否無效有爭議，其實是對預設行為有爭議，應該透過實際執行文件來解決，而不是辯論。當一個句子不通過時，刪掉整個句子，而不是刪掉幾個字。這個判準也能用來評估主導詞：太弱、贏不過預設的詞（當 agent 本來就算周到時說「要周到」）就是無效指令，解法是換一個更強的詞（_relentless_），而不是換一種技巧。
